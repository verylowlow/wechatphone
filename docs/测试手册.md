# wechatphone 测试手册

> 基线版本（2026-08-10 实测）：微信 4.1.12.26 / 企业微信 WXWork.exe / 钉钉 DingTalk.exe（含定制改名版，按窗口类名定位，不依赖标题）。
> 全部命令在项目根目录执行，Python 用 `.venv\Scripts\python.exe`。

## 1. 测试矩阵

| 层 | 项目 | 命令/方式 | 通过标准 |
|---|---|---|---|
| L1 API | Realtime 文本回复 | `test_api_text.py` | 打印 AI 回复文本 |
| L1 声卡 | CABLE 穿透 | `test_inject.py` | 打印 `INJECT TEST: PASS` |
| L1 知识库 | 检索冒烟 | `tools/test_kb.py` | 打印 `PASS: knowledge smoke test` |
| L2 音频链路 | 全链路 | `bridge.py` + `ffplay tools/test_voice.wav` | 电平升高→speech_started→转写→AI 回复→response.done |
| L3 UI-微信 | 拨号+挂断 | `cli dial 助理GPT` / `hang_up` | 拨出等待接听；红圆挂断 ok |
| L3 UI-企微 | 七步全流程 | `tools/wecom_e2e_test.py` | RESULT: OK，七步截图齐 |
| L3 UI-钉钉 | 七步全流程 | `tools/dingtalk_e2e_test.py` | RESULT: OK（连跑 3 次全绿） |
| L4 记录 | 通话记录 | 通话后看 `calllog_app.py` | 列表/时间线/摘要正确 |

## 2. 免真机自检（先跑这组）

```bash
.venv\Scripts\python.exe test_api_text.py          # API 自检, 不依赖音频
.venv\Scripts\python.exe test_inject.py            # 虚拟声卡穿透
.venv\Scripts\python.exe tools\test_kb.py          # 知识库检索
```

## 3. 全链路音频自测

```bash
.venv\Scripts\python.exe bridge.py
# 另开终端往物理扬声器播人声:
ffplay -nodisp -autoexit tools/test_voice.wav
```

预期日志序列：电平升高 → `speech_started` → `[对方说] ...` → AI 回复文字 → `response.done`。

## 4. UI 自动化回归

### 4.1 窗口探测（换机器/换版本第一步）

```bash
.venv\Scripts\python.exe -m autodial.cli windows
```

确认微信/企业微信主窗口"找到"。

### 4.2 微信 4.1 回归

```bash
.venv\Scripts\python.exe -m autodial.cli dial 助理GPT --app wechat --dry-run   # 预演
.venv\Scripts\python.exe -m autodial.cli dial 助理GPT --app wechat             # 实拨(测试号不接听)
# 挂断 (bridge 运行时 AI 会自动挂; 单测可用 hangup 模块)
```

检查点：拨出后出现"等待对方接受邀请"；挂断后聊天出现"已取消"。

### 4.3 企业微信回归（七步全流程）

前置：企业微信已登录、主窗口存在、通讯录中有唯一精确名称的测试客户（如"高原"）。

```bash
# 一键端到端 (每步截图 data/wecom_step1..7.png): 激活→通讯录→搜索→点首条→语音通话→呼叫确认→红圆挂断
.venv\Scripts\python.exe tools\wecom_e2e_test.py

# 官方入口验证:
.venv\Scripts\python.exe -m autodial.cli dial 高原 --app wecom
.venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'.'); from autodial import hangup; print(hangup.hang_up('wecom'))"
```

通过标准：
- 步骤3 OCR 精确命中恰 1 条（多条=名称重复，按设计终止）；
- 步骤6 截图含"正在呼叫"与大红圆；
- 步骤7 挂断返回 `{'ok': True, 'method': 'wecom_red_circle'}`，且挂断后无红圆。

### 4.4 钉钉回归（七步全流程）

前置：钉钉（含定制改名版）已登录、通讯录搜索结果唯一（如"北五7班16号张若初"）。
**注意：e2e 运行期间请勿人工操作鼠标/键盘（共享桌面会抢焦点）。**

```bash
# 一键端到端 (每步截图 data/dt_step1..5.png):
# 激活→通讯录(UIA)→搜索(清除+精确)→联系人tab→行尾语音图标→呼叫确认→红圆挂断
.venv\Scripts\python.exe tools\dingtalk_e2e_test.py

# 官方入口验证:
.venv\Scripts\python.exe -m autodial.cli dial 北五7班16号张若初 --app dingtalk
.venv\Scripts\python.exe -c "import sys; sys.path.insert(0,'.'); from autodial import hangup; print(hangup.hang_up('dingtalk'))"
```

通过标准：
- 步骤3 OCR 精确命中结果行（排除顶栏搜索框自身）；多条同名按设计终止；
- 步骤4 模板 `data/dt_voice_btn.png` 匹配行尾语音图标，进入"正在呼叫"小面板；
- 挂断返回 `{'ok': True, 'method': 'dingtalk_red_circle'}`，挂断后面板消失。

### 4.5 来电自动接听回归

用另一台设备/手机对本机账号发起语音来电，观察 bridge 日志：
`[INCOMING] 检测到来电 ... 已接听`；视频来电默认跳过。

## 5. 批量拨打回归

```bash
printf "高原\n" > data/names_test.txt     # 或手写 tasks.json
.venv\Scripts\python.exe -m autodial.cli batch data/names_test.txt --app wecom --task "回归" --gap 20
```

检查点：逐条打印 `({i}/{total}) 拨打`；上一通结束后才拨下一个；结果 JSON 全 `dialed`。

## 6. 通话记录回归

```bash
.venv\Scripts\python.exe calllog_app.py     # http://127.0.0.1:8766
```

检查点：列表有时长/事件数/摘要；详情页对方转写、AI 回复、KB 工具调用气泡齐全；
重复名称终止会生成"xxx名称重复, 未执行呼叫"记录。

## 7. 已知限制 & 回归注意

- 截图在会话预览中**非等比缩放**：校准/改坐标一律以 OCR/像素实测为准，禁止目测。
- 企业微信头像菜单陷阱：误弹后 Escape 会隐藏主窗（截图全黑属正常），重新激活即可。
- 微信菜单第一项语音/第二项视频：勿点第二项。
- 颜色连通域阈值：挂断红圆/接听绿圆 面积≥2500 且近圆，勿用"任意红/绿像素"（误中红点/绿标）。
- 钉钉（含定制改名版）：左侧导航 UIA 可用、内容区视觉方案 dingtalk_vision 已实测；
  搜索弹页 Ctrl+Shift+F 为 toggle 且有"关闭过渡态"，e2e 期间禁止人工并发操作。
- 单实例单通话；批量必须先起 bridge.py。
